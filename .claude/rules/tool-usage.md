# ツールエラー防止

- **ファイル操作前に存在確認**: `Edit`の前に`Read`で対象ファイルの存在と内容を確認する
- **長時間コマンドのtimeout**: 10秒以上かかりそうなBashコマンドは`timeout`パラメータを明示する
- **破壊的操作の事前確認**: `git push --force`, `git reset --hard`, `rm -rf`等は実行前にユーザーへ意図確認
- **パス存在チェック**: ディレクトリ作成・ファイル書き込み前に親ディレクトリの存在を確認
- **対話式コマンドのガイド**: `npm create`、`npx create-*-app` 等の対話式プロンプトを含むコマンドはユーザーが手動実行する。AIは事前に以下を提示する:
  1. 実行するコマンド全文
  2. 各プロンプトで**推奨する選択/入力値**とその理由
  3. 「全選択」等のまとめ選択がある場合、**選択すべき項目・外すべき項目**を明示
  4. AIから非対話で値を渡す必要がある場合（例: `wrangler secret put`）は `printf '%s' "$VALUE" | cmd` のパイプ渡しにし、値を画面に出さない
- **非対話環境でのsecret登録は成功表示を信用しない**: 対話式secret登録コマンドは、非対話環境（AIのbash実行含む）だとstdinが空のまま「Success」を返し、空値が保存されることがある。登録後は**実際の動作（APIの実応答等）で検証**する
- **ビルドスクリプトの許可は設定ファイルで非対話化**: `pnpm approve-builds` 等の対話式許可コマンドの代わりに、設定ファイル（例: `package.json` の `pnpm.onlyBuiltDependencies`）に対象パッケージを明示列挙してから再インストールする
- **新規外部ドメイン/サブドメインの発行直後は伝播ラグを疑う**: DNS/TLS証明書発行には数分〜十数分のラグがあり得る。直後の接続エラーは設定ミスと決めつけず、時間を置いた再検証（バックグラウンド監視でも可）を優先する
- **外部連携は全層検証してから「接続済み」と言う**: (a) 外部ツール連携（MCP等）は、手作業・非公式手段より先に**公式コネクタの存在を確認**する。(b) 接続状態は構成要素の一部（サーバ起動のみ等）でなく、**実際の操作が一往復通ったことを確認してから**「接続済み/ready」と報告する。層が複数ある場合（サーバ＋アドオン等）は各層を列挙して検証結果を添える。未検証の成功報告はでたらめな引用と同種の禁止事項として扱う

## ガード系フックの検証（fail-closed）
> 「守られているつもり」が最も危険。ガードは効いていないことが黙って起こる。

- **配布したガードは「実体・登録・テスト」の3つがそろって初めて接続済み**: フックのファイルが届いても、`settings.json` に登録されていなければ一度も動かない。配布したら `apply_template.sh` の差分表示とテスト結果を見て、足りない登録を足す
- **AIが実際に打つコマンド形で検証する**: 人間は `cd` してから `git commit` するが、AIは移動不要な `git -C <path> commit` を好む。人間の手癖を前提にしたパターンマッチはAI相手では抜ける
- **判定不能は止める（fail-closed）**: 対象を特定できないまま通す実装は「守られている」誤認を生み、ガードが無いより悪い
- **通す/止める両方を実測する**: 書いて終わりにしない。フック単体を叩く検証スクリプトを置き、修正のたびに流す（例: `.claude/hooks/test-git-branch-guard.sh`）
  - **フック以外の確認コマンドも同じ**: 確認・集計のコマンドを書いたら、「必ず1件は引っかかる入力」と「1件も引っかからない入力」の両方で動かす。全件ダメと出れば気づけるが、**全件通る壊れ方は気づけない**
    - 例: 外部 CLI の JSON 出力では、日本語などの非 ASCII のキー名が文字化けして返ることがある。そのキーで存在チェックすると常に false になり、「全件未設定」と誤報する。非 ASCII のキー名を条件に使うときは、CLI の整形出力ではなくサービスの API を直接呼んで、返ってきた生のフィールド名と突き合わせる
- **同じ欠陥はファイル内に複数ある前提で探す**: 同じ書き方が別の判定箇所にも使われている。片方だけ直すと穴が残る
- **一括処理の検証は、処理と同じ条件で数えない**: 一括置換・一括適用は、条件に合わない要素（1つの要素の中で値が混在しているもの等）を**エラーなしで飛ばす**。飛ばした条件を別の条件で数え直す
- **書いたものを見るガードは、書かなかったものを見ない**: 「書いた値が正しいか」の照合は、そもそも照合を通っていないもの（直書きの文言等）を見つけられない。差分の可視化フック（`show-ssot-diff.sh`）も「入ったこと」しか見せず、入るべきものが入っていない欠落は映らない。網の外を数える検算を別に置く

## サブエージェントの結果が返らないとき（黙って詰まる）

> ガードと同じで、**「回っているつもり」が最も危険**。タイムアウトもエラーも出ずに待ち続ける形になる。

- **「重い処理だ」と決めつける前に実測する**（`dev-practices.md`「思い込みより実測」のサブエージェント版）
- 診断はログを見る:
  ```
  ~/.claude/projects/<project-dir>/<session-uuid>.jsonl
  ```
  | 見るもの | 意味 |
  |---|---|
  | `type=system, subtype=turn_duration` | **完走している**。あとは配送の問題 |
  | `type=assistant` の text ブロック | **結果はここに残っている**（最悪ここから回収できる） |
  | `No such tool available: SendMessage` | **返す手段が無い**まま終わっている |

- **根本原因になりやすいのは、エージェント定義の `tools:` に `SendMessage` が無いこと**
  - `teammateMode: tmux` では、サブエージェントは**独立セッションのチームメイト**として走る
  - チームメイトは**最終テキストを親に自動返却しない**。`SendMessage` で明示的に返す設計
  - → `tools:` を絞るときは **`SendMessage` を必ず残す**
  - → ⚠️ **tools に足すだけでは足りない。** 定義本文に「結果は SendMessage で返す」と**明記する**
    （足しただけだと「最終テキストで返る」と思い込んで使わない）

- ⚠️ **同じ欠落は全エージェント定義にある前提で点検する**（`.claude/agents/*.md` を横断で確認）
