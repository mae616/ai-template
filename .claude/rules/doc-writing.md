# ドキュメントの書き方と置き場（常時）

> 目的: **AI が読み切れる量に保ち、読んだものが現行だと信じられる状態にする。**
> リポジトリが膨らむと、AI は違うものをモデル化する。整理整頓ではなく、判断の正しさの話。

## 1. 値 / 判断 / 履歴 を、同じファイルに混ぜない

| 層 | 何を持つか | 形 | いつ読むか |
|---|---|---|---|
| **① 値** | 確定した数値・色・サイズ・文言の実体**だけ** | 機械可読（JSON / トークン） | 実装・生成が引く |
| **② 判断** | なぜその値か／いつ使うか／使わない場面 | 文章（ルール・スキル・デザインドック） | **作る前** |
| **③ 履歴** | 何を試して、何が違って、何を捨てたか | git と、§2 で名指しした置き場 | 方針を疑うときだけ |

- 値 ＋ 判断: 引きたいだけなのに長文を読む。表の1セルに長文が入り、一覧できなくなる
- 値 ＋ 履歴: 捨てた値と生きている値が並び、どれが現行か読めない
- 判断 ＋ 履歴: 失敗の実例が毎回読まれ、警戒が上がって本当に効く警告が埋もれる

## 2. 履歴を積んでよいファイルを、名指しで決める

積んでよいのは次の置き場だけ。プロジェクトで増やすときは、ここに名指しで足す。

| 置き場 | 積むもの |
|---|---|
| `history/`（git 管理外） | 日々の引き継ぎ・作業ログ |
| `meta/adr-lite.md` | 判断の経緯（ADR） |
| `doc/generated/reports/` | 日付つきのレポート |
| `doc/draft/` | 発酵中・未合意の検討物（決定ログを含む）。合意したら `doc/input/` や rules へ移し、ここは畳む |
| `meta/`（ai-template 自身のときだけ） | ADR・レポート・決定ログ（`meta/draft/`）。ai-template では `doc/` に記録を書かない |

**それ以外は、古くなったら書き換える。積まない。** 「以前はこう、いまはこう」を積んだ時点で、そのファイルは履歴に戻っている。消すのが怖いものは git が持っている。

## 3. 写しを作らない。照合する時点を決める

- 同じ内容を2か所に持たない。持つなら **①どちらが正か ②変えるときは両方直す** を書く
- **「値の正は◯◯」と書くだけでは効かない。宣言は照合の代わりにならない。** 照合する時点を決める（作る直前／値を変えたとき／画面や決めごとを足したとき）
- 決めごとを足した直後は、既存の実物に必ず違反が出る。足すことと実物を合わせることは別の作業なので、足した時点で違反の件数を数えておく
- 別のツール用に複製が要ると思ったら、まずシンボリックリンクを試す。複製は必ずずれる

## 4. 引ける形にする

- 索引を持つ（「いま何をしているか → 読む項目」の対応表）
- 1項目 = 1見出し。表のセルに長文を入れない
- 1ファイルが 300行を超えたら、主題で割れないかを疑う

## 5. 未決を「無い」と書かない

「**決めていない**」と書く。「無い」と書くと、読んだ側（AI 含む）が自分で決めてよいと解釈する。
値のファイルには、**確定か暫定かの区別**と **`undecided`（決めていない項目）の節**を必ず持つ。キー名は既存のスキーマとぶつけない（例: デザイン SSOT の `status` は素材の取得結果 ok / failed に使われているので、確定度は別のキーにする）。

## 6. 分割・移行は、機械で切り出して検算する

手で写すと必ず落ちる。

1. 機械で切り出す
2. 元の項目数と、振り分け先の合計を突き合わせる（漏れ0・重複0）
3. **消す前に、昇格し損ねを機械で照合する**（元側の結論らしい行を全部抜き、移行先にあるか当て、見つからないものを人が見る）

## 7. 止めた・消した判断こそ、書いて残す

- 止めるときは **①いつ ②なぜ ③代わりにどこを見るか ④再開する条件** を書く。期限も再開条件も無い「いったん止める」を作らない
- **また作れるもの（生成物）は、凍結せずに初期化する。** 残して「使うな」と書くと、古い値を引く経路が生きたままになる。消すときは、復元できるコミットと、次に作るときの作法（確定値から作る）を置き場に残す

## 8. 読む側の決めごと（書くだけでは効かない）

- セッション開始時: `/setup` で引き継ぎ・前提・環境を読む
- 作る直前: その作業に当たる索引を引く（全部は読まない）

## 9. 定期的に測る

「重い気がする」で判断しない。数える。

```bash
git -c core.quotePath=false ls-files -z '*.md' '*.json' | xargs -0 cat | wc -l      # 総行数
git -c core.quotePath=false ls-files -z '*.md' | xargs -0 wc -l | sort -rn | head -20 # 大きい順
# 日付見出しを積んでいるファイル（§2 の置き場以外が出たら疑う）
git -c core.quotePath=false ls-files -z '*.md' | xargs -0 grep -cE '^#{1,3} .*20[0-9]{2}-[0-9]{2}' /dev/null | grep -v ':0$'
```

`history/` は git 管理外なので、この測定には入らない。

重複はディレクトリ単位で起きる。同じ木が2つ無いかを最初に見る。
