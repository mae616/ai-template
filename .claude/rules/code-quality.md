# AI運用ガイドライン（CLAUDE.md補足）

## サンプルコード運用
- 原因切り分け・最小検証のためだけに作成（プロダクション流用しない）
- 配置: 実行系から参照可能な `samples/` に切る。本番ビルド・配布からは除外
- 命名: `sample_{short-purpose}.{ext}`、先頭コメントに「一時利用・削除可」明記
- 実鍵・個人情報・API Key・本番エンドポイント禁止（モック/ダミー値）
- ビルド/テスト/カバレッジから除外。解決後は同PRで削除

## 依存（ライブラリ）評価の補助基準
- 評価観点: 直近リリース日、Issue応答、ドキュメント質、DL数/週、互換性、代替案の有無

## 危険変更チェックリスト（手動確認が必要な変更）
> 一人開発の見落とし・損害賠償リスクを減らすための関所。仕組み（hook/CI）が未整備な範囲を手動確認で補う。

触った変更/PRが以下のいずれかを含む場合は**厚く見て、人間に明示確認**する:
- [ ] 認証・認可
- [ ] 決済
- [ ] 個人情報
- [ ] DBマイグレーション
- [ ] 権限設定
- [ ] 外部API連携
- [ ] 削除処理
- [ ] 通知・メール送信

- セキュリティ項目（認証/認可/個人情報/外部API等）の**詳細な判断軸は `security-expert` スキル**が担う
- このチェックリストは「変更時の関所」として**全変更に常時適用**し、運用リスク（DBマイグレーション/削除/通知）も含めて取りこぼさない役割

## スコープ外追加の三条件ガード
Issueに明記されていない追加実装は、次の3条件を**すべて**満たす場合のみ許可する:
1. プランまたはPR本文で採用理由を宣言済み
2. 値・文言はSSOT（トークン/コピー）経由（直書きしない）
3. テスト可能（純粋関数）またはエビデンス（スクリーンショット/実測）付き

満たせないものは実装せず、「後続タスク提案」として出す。

## ADR-lite（変更要求）テンプレ
- Context: 何が前提で何が問題か
- Decision: 何を決めるか（選択肢A/Bと比較）
- Consequences: 影響（メリット/デメリット/運用/コスト）
- Alternatives: 採用しない案と理由
