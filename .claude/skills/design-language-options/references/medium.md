# Figma か、コードか（媒体の判断）

選択肢を見せる媒体（Figma / コード / 併用）を、**確かめたい問いから逆算して決める**。
人間がまだこの判断に慣れていない前提で、AI が毎回この基準を通して推奨と理由を出し、人間が承認する。

## 基準の核

> **止まっている絵で判断できるなら Figma。動かさないと分からないならコード。**

## 判断フロー（上から順に、最初に当てはまったものを採る）

1. **触った感触・動き・入力感が体験の核心か？** → **コード**（hover・スクロール・アニメーション・タイピング感は Figma では嘘になる。モーション言語の比較はたいていここ）
2. **実データ・実ロジックが体験を左右するか？**（速度・データ量・エッジケース） → **コード**
3. **色・タイポ・レイアウト・トーンの比較か？** → **Figma**（複数案を並べて見るのが得意。手で微調整もできる）
4. **画面遷移・情報設計を俯瞰して合意したいか？** → **Figma**（画面一覧と流れを1枚で見せられる）
5. **デザインシステム・トークンの整備か？** → **Figma**（`/design-ssot` で値を実装へ流せる）
6. **どれでもない・迷う** → **併用**: Figma でトーンを並べる → 良かった方向をコードで動かして確かめる

## 早見表

| Figma が向く | コードが向く |
|---|---|
| 色・タイポ・レイアウトの比較（複数案を並べる） | hover・スクロール・アニメーションの触感 |
| 画面一覧・遷移の俯瞰 | 実データ・待ち時間・データ量が効く体験 |
| トークン・コンポーネントの整備 | 技術的に成立するかの検証 |
| 人に見せて合意を取る資料 | レスポンシブの実際の挙動 |
| 手で微調整したいもの | 動きに世界観が宿る表現（生成的・ゲーム的） |

## 運用

- 決めたら**推奨と理由を一言**で人間に出し、承認を得てから作る（判断を人間が学べるよう、理由は必ず言葉にする）
- 1ラウンドの中での併用は可（例: Figma で3トーン並べて選ぶ → 選ばれたトーンをコードで動かす）
- Figma 側の実作業は Figma プラグインのスキル（書き込みは `figma-use` / `figma-generate-design`）、実装への引き渡しは `design-ssot`。Figma が使えない環境では、静止画の比較も HTML で作る
- Figma の URL は設定集に書いて揮発を防ぐ

## よくある誤り

- 「デザインの話だから」と何でも Figma に寄せる（動きが核心の体験は Figma では確かめられない）
- 「どうせ実装するから」と何でもコードで作る（トーンの比較は Figma の方が速く、開発者以外とも共有できる）
- 併用したとき、Figma とコードで別々に判断して分かれる（結論は設定集に1本化する）
