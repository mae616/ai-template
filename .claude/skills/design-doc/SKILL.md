# design-doc — 「なぜこうなっているか」を、引ける形で書く

## このスキルが解く問題

デザインの記録は、たいてい日付つきの回で積まれる。書きやすいが、**知りたいことと形が合っていない**。

| 記録の形 | 知りたいこと |
|---|---|
| いつ・何を試したか | **この画面は、どういう考慮で、こうなっているのか** |

時系列を遡っても答えは出ないので、毎回その場で決め直し、画面ごとにバラバラになる。さらに、古い回が現役の顔をして読まれ、**昇格し損ねた判断に誰も気づかない**。

> **書き込みの関所**: `doc/input/design/` への書き込みは、`.claude/rules/dev-practices.md`「一時と確定を分ける」に従う（文面か差分を見せて合意を取る。判断盤で選ばれたものはまとめて書いてよい。自律ループ中は `doc/draft/` に候補として置く。値のファイルの仮の値は同節の「例外」に従う）。

## 発火条件

- 決めたことを**書き足す**とき（毎回）
- デザインの決めごとが画面ごとにバラつくとき
- 記録（設定集・連作ログ・議事録）が増えて読まれなくなったとき
- 新しいプロダクトで、最初からこの形で始めるとき

## デザインドックとは

**主題ごとに「決まっていること」と「なぜそうなっているか」を書いたもの。** 置き場は `doc/input/design/docs/`（索引は同ディレクトリの README）。

| 書く | 書かない |
|---|---|
| いまの結論 | 時系列（「いつ決めて、いつ変えた」） |
| そう決めた理由・考慮した制約 | 失敗の実例 |
| 当てるときの手順・迷ったときの分岐 | 値そのもの（→ `doc/input/design/*.json`） |
| **まだ決めていないこと** | 却下した案の詳細（結論に効くものだけ1行） |

1本の形は `doc/input/design/docs/README.md` にある。⚠️ 「まだ決めていない」を空にしない。空だと「全部決まっている」と読まれ、読んだ側が未決の場所を埋める。

**主題で切る（画面で切らない）**。画面ごとに切ると、共通の規則が画面の数だけ重複する。主題ごとなら、画面が増えてもドックは増えない。例外は、その画面にしか無い事情が大きいときだけ。

## 書くときの決めごと

1. **古くなったら書き換える。積まない。** 「以前はこう、いまはこう」と積んだ時点で時系列の記録に戻る。前の版は git が持っている
2. **理由と一体の値だけ、本文に書いてよい。** 理由と切り離すと誤用される値（例: 「上余白は多数派より大きい値を採る。多数派の値だと端末の時計と重なるため」）は、理由と並べて書く。そのとき値のファイルとの二重持ちになるので、**どちらが正か**を書く
3. **決め手になった人の言葉は、要約せずに引く。** 要約すると、なぜそれが決め手だったのかが消える
4. **原則どうしの上下を書く。** 書いていないと、下位の規則が上位の原則を黙って破る（例: 「警告色は使ってよい唯一のケースを決めたもので、使わなければならないではない」）

## 常に最新に保つ

### 学んだことの行き先は5つだけ

| 学んだこと | 行き先 |
|---|---|
| 結論（こうする、と決まった） | デザインドックの該当する主題に**書き換えて**入れる |
| 値（色・サイズ・寸法・文言） | 値のファイル（`doc/input/design/*.json`） |
| 検証中の学び（まだ結論でない） | 設定集（`doc/draft/design/setting-book/`）。結論になったらドックへ書き換えて移す |
| 経緯（何を試して何が違ったか） | コミットメッセージ |
| 回の一行記録 | 索引の表に1行 |

⚠️ 新しい記録ファイルを増やさない。増やした瞬間、6つ目の置き場ができる。

### 索引に「結論の行き先」を持つ

連作や検証の回を記録するなら、索引の表に**結論の行き先**の列を持つ。**空欄＝昇格し損ね。** これが唯一の検出手段。

## 移行するとき（時系列の記録が溜まっている場合）

`.claude/rules/doc-writing.md` §6 の手順で行う（機械で切り出す → 検算 → 消す前に昇格し損ねを照合）。手順3を飛ばすと、移行そのものが昇格し損ねを作る。

## 新しいプロダクトで最初からやる

1. 索引（README）と、空のドックを主題ごとに作る（空でも作る。決まったものの行き先が先にある状態にする）
2. 値のファイルを空で置く（`undecided` に「まだ決めていない」を書く）
3. 最初の画面を描く。決まったことは、その場でドックへ
4. 主題が足りなければドックを足す（回の記録は足さない）

⚠️ 「あとでまとめて書く」にしない。その場で書かないと、会話の中にしか無い状態になる。最初から全部埋めない。触っていないものは「まだ決めていない」と書いて進む。

主題の叩き台: コンセプトと体験原則／画面の骨格／出口と戻り／ボタンとリンクと入力欄／アイコンと記号／言葉づかい／保存と中断／確認と警告／色と質感と文字／モーション。⚠️ この一覧をそのまま使わず、最初の5画面で出た論点で決める。

## よくある落とし穴

- 時系列の記録を残したまま、ドックも作る（二重になり、どちらが現行か読めない）
- ドックに日付つきの節を足していく（時系列の記録に戻っている）
- 「まだ決めていない」を空にする
- 値をドックに書き写す（値のファイルと二重になり、変えたとき片方だけ直る）
- 移行のときに手で写す
- 主題ではなく画面で切る
