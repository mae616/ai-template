# 文字と階層 — 読む順番を、見た目で決める

> 出典: Adam Wathan / Steve Schoger『Refactoring UI』（強弱は大きさだけでなく太さと色で付ける）、Robert Bringhurst『The Elements of Typographic Style』（行長・行間）、Ellen Lupton『Thinking with Type』（階層）。

## 原則と当てる問い

### 1. 階層は「大きさ」だけで付けない

強弱の手がかりは **大きさ・太さ・色（濃淡）・位置・余白** の5つ。大きさだけで階層を作ると、見出しが大きくなり続けて画面がうるさくなる。

- 一番大事なものは、5つのうちどれで目立たせているか
- 補足は「小さくする」より先に「色を薄くする」で下げられないか
- 見出しと本文の差が**少しだけ**になっていないか（本文「対比」：違えるならはっきり）

### 2. 階層の段数を絞る

1画面で使う文字サイズは**数種類**に絞り、決めた段（スケール）からだけ選ぶ。

- この画面に文字サイズは何種類あるか。プロジェクトの決めたスケール以外の値が混ざっていないか
- 同じ役割（例: 画面タイトル）が、画面によってサイズや太さが違っていないか

### 3. 読ませる文の形

- **行長**: 本文の1行が長すぎると、次の行の頭を見失う。欧文はおよそ45〜75字が目安とされる。和文は1行に収める文字数を、プロジェクトで決める
- **行間**: 本文は詰めすぎない。見出しのような大きな文字は、本文より行間を詰める
- **揃え**: 長い文は左揃え。中央揃えは短い一言だけ（複数行を中央揃えにすると、行頭が毎行ずれて読みにくい）

当てる問い:
- 3行以上の文を中央揃えにしていないか
- 長い文が画面幅いっぱいに伸びていないか（最大幅を決めているか）

### 4. ラベルと値

- フォームや詳細表示で、ラベルと値のどちらが主役か決めたか（値を読ませたいならラベルを薄く・小さく）
- 数字が縦に並ぶ表で、桁が揃って見えるか（等幅数字）

## よくある壊れ方

- 全部の見出しが太字で大きく、どれが一番か分からない
- 補足の文字を小さくしすぎて読めない（下げるなら先に色）
- 強調が多すぎて、強調の意味が消えた（太字・色・下線を同時に多用）
- 画面ごとにタイトルのサイズが微妙に違う
