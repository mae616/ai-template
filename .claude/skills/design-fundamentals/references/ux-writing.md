# UI の文言 — 言葉もデザインの部品

> 出典: Kate Moran「The Four Dimensions of Tone of Voice」（NN/g, 2016。https://www.nngroup.com/articles/tone-of-voice-dimensions/ で確認済み）、Torrey Podmajersky『Strategic Writing for UX』、Kinneret Yifrah『Microcopy: The Complete Guide』、Steve Krug『Don't Make Me Think』。
> ⚠️ ここは一般則。**このプロダクトの声（語り口・トーン）は `project-design-language` の「声・トーン」で決める**。決まっていなければ「未決」として人間に聞く。

## 声とトーンを分ける

| | 何か | 変わるか |
|---|---|---|
| **声（ボイス）** | プロダクトの人格。誰が話しているか | 変わらない（全画面で同じ） |
| **トーン** | 場面に合わせた話し方 | 変わる（成功・エラー・お願い・待ち時間で調整する） |

トーンを決めるときの4つの軸（NN/g）:

1. 改まった ↔ くだけた
2. 真面目 ↔ ユーモアがある
3. 丁寧 ↔ 型破り
4. 淡々と ↔ 熱っぽく

→ プロダクトの声を、この4軸の位置で決める。場面ごとのトーンは、その位置から**どちらに寄せるか**で決める（例: エラーは真面目・淡々と寄り、完了は少し熱っぽく寄り）。

## 当てる問い

### 1. 利用者の言葉で書いているか

- 内部の用語・データベースの名前・技術用語が画面に出ていないか
- 同じものを、画面によって違う言葉で呼んでいないか（本文「反復」の言葉版。**用語集**をプロジェクトで持つ）

### 2. ボタンは「何が起きるか」を言っているか

- 「OK」「はい」ではなく、押すと起きること（「削除する」「保存する」「送る」）を書いているか
- 確認ダイアログで、ボタンの文言だけ読んでも選べるか

### 3. エラーは「何が起きて、どうすればよいか」を言っているか

- 何が起きたかを、責めずに平易に言っているか（利用者のせいにしない）
- 次に何をすればよいかが書いてあるか
- 謝りすぎていないか、曖昧ではないか

### 4. 短く、前に置く

- 大事な言葉を文の頭に置いているか（拾い読みされても伝わるか）
- 説明文の半分を消しても伝わらないか

### 5. 空の状態・待ち時間・完了

- データが空の画面で、次に何をすればよいか言っているか
- 待ち時間に、何をしているかを言っているか
- 完了のときに、何が終わったか・次に何が起きるかを言っているか

## よくある壊れ方

- 同じ操作が「削除」「消去」「取り消し」と画面ごとに違う
- ボタンが「OK／キャンセル」で、何が OK なのか分からない
- エラーが「エラーが発生しました」だけ
- 声が画面ごとに変わる（ある画面は敬語、別の画面はくだけた口調）
- 文言の値（実際の文字列）が画面に直書きされ、用語集やコピーのファイルと食い違う
