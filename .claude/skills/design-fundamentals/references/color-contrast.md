# 色とコントラスト — 色は「意味」に割り当てる

> 出典: W3C WCAG 2.2（SC 1.4.1 色の使用 / 1.4.3 コントラスト（最低限）/ 1.4.11 非テキストのコントラスト）、『Refactoring UI』（色の役割を先に決める）。
> 数値は公式で確認済み: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html / https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html

## 基準の数値（WCAG 2.2・レベル AA）

| 対象 | 最低コントラスト比 |
|---|---|
| 本文の文字 | **4.5 : 1** |
| 大きい文字（18pt 以上、または 14pt 以上の太字。およそ 24px / 18.7px 太字。和文は「同等の大きさになる文字サイズ」で判断する、と WCAG が注記している） | **3 : 1** |
| 操作部品の輪郭・状態の表示、意味を持つアイコンや図 | **3 : 1**（隣り合う色に対して） |

⚠️ 一般則の最低ラインであって、目標値ではない。プロジェクトが決めた値（感覚過敏への配慮でコントラストを抑える等）があればそちらに従う。**下限を割ると WCAG 2.2 AA を満たさなくなる**ので、割るときはそのことを示して人間に確認する（判断軸は `accessibility-engineer`）。

## 原則と当てる問い

### 1. 色の役割を先に決める

色は「きれいだから」ではなく**役割**に割り当てる（主役の操作／背景／文字／状態（成功・注意・危険）など）。

- この色は何の役割か、一言で言えるか
- 同じ役割に2色以上使っていないか。違う役割に同じ色を使っていないか（ゲシュタルトの類同で同じ物に見える）
- 危険の色（赤など）を、取り返せない操作以外に使っていないか

### 2. 色だけで意味を伝えない（SC 1.4.1）

色が見分けられない人・環境でも伝わるように、**形・文字・アイコンを併用**する（本文「対比」の2つの手がかり）。

- エラーを赤色だけで示していないか（文言やアイコンもあるか）
- グラフや状態を、色の違いだけで区別していないか

### 3. 面の色は控えめに

- 強い色の面がいくつあるか。目が休まる場所はあるか
- 背景と主役の色が近く、主役が沈んでいないか（ゲシュタルトの図と地）

## よくある壊れ方

- 薄いグレーの文字で「上品」にしたら、コントラストが足りず読めない
- 無効状態のボタンが、有効なボタンと見分けられない（または逆に、読めないほど薄い）
- ダークモードで、ライトモードの色をそのまま反転して、強調色が浮きすぎる
