# UX の法則 — 数・距離・時間の目安

> 出典: Jon Yablonski『Laws of UX』（https://lawsofux.com/ で一覧を確認済み）、W3C WCAG 2.2 SC 2.5.8（https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html で確認済み）、Apple Human Interface Guidelines、Material Design。
> ⚠️ 法則は傾向であって定理ではない。数値は目安として使い、プロジェクトの決定と実測を優先する。

## 押しやすさ・選びやすさ

| 法則 | 一言で | 当てる問い |
|---|---|---|
| フィッツの法則 | 目標が遠く小さいほど、押すのに時間がかかる | よく使う操作は、大きく・指の届く位置にあるか。危険な操作が、よく使う操作の隣にないか |
| ヒックの法則 | 選択肢が多く複雑なほど、決めるのに時間がかかる | 一度に見せる選択肢を絞れないか。おすすめを示せないか |
| 選択過多 | 選択肢が多すぎると、選べなくなる | 同上。比較させたいなら、比べる軸を揃えて見せているか |
| ミラーの法則 | 一度に覚えておける量には限りがある（7±2 とされる） | 利用者に、画面をまたいで覚えておかせていないか |
| チャンク化 | 情報は意味のまとまりに区切ると扱いやすい | 長い数字・長いリストを、意味の単位で区切っているか |

**タップ領域の数値**

| 基準 | 最小サイズ |
|---|---|
| WCAG 2.2 SC 2.5.8（レベル AA） | **24 × 24 CSS px**（例外あり: 十分な間隔がある場合など） |
| Apple HIG | 44 × 44 pt |
| Material Design | 48 × 48 dp |

⚠️ WCAG の値は下限。モバイルでは各プラットフォームの値を目安にし、プロジェクトの決定に昇格させる。見た目のアイコンが小さくても、**押せる範囲**を広げればよい。

## 慣れ・記憶・印象

| 法則 | 一言で | 当てる問い |
|---|---|---|
| ヤコブの法則 | 人は、よく知っている他のサイト・アプリと同じ動きを期待する | 独自の操作にする理由はあるか。慣習どおりで済むなら慣習に従う |
| フォン・レストルフ効果 | 周りと違う1つが記憶に残る | 一番目立たせたい1つだけが違っているか（目立つ物が複数あると効かない） |
| 系列位置効果 | 並びの最初と最後が記憶に残る | 大事な項目を、リストの真ん中に埋もれさせていないか |
| ピーク・エンドの法則 | 体験は、一番強い瞬間と終わり方で評価される | 完了の瞬間・終わり方は丁寧に作られているか |
| 美的ユーザビリティ効果 | 見た目が整っていると、使いやすいと感じられる | ⚠️ 逆に言えば、見た目の良さが使いにくさを隠す。見た目で評価を済ませていないか |
| テスラーの法則 | どのシステムにも、消せない複雑さがある | その複雑さを、利用者と作り手のどちらが引き受けているか |

## 待ち時間

| 法則 | 一言で | 当てる問い |
|---|---|---|
| ドハティのしきい値 | 応答がおよそ 400ms 以内だと、人も機械も待たずに作業が進む | 400ms を超える処理に、進んでいることの表示があるか |
| 目標勾配効果 | ゴールが近いほど、人は頑張れる | 複数手順の操作で、残りがどれだけか見えているか |

## よくある壊れ方

- 小さなアイコンボタンが、押せる範囲も小さいまま
- 設定画面に選択肢を全部並べ、何を選べばよいか分からない
- 目立たせたい物が多すぎて、どれも目立たない
- 処理中の表示が無く、壊れたと思われる
