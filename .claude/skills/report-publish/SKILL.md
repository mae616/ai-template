# report-publish — レポートと判断盤を作り、保存して見せる

## いつ使うか

| 出すもの | いつ |
|---|---|
| **レポート** | 概念説明・設計説明・アーキテクチャの説明・「何をやったのか」の作業報告を求められたとき（`CLAUDE.md`「概念・設計説明の可視化」） |
| **判断盤** | 人間に項目ごとに選んでもらうとき（`design-language-options` の手順5、`auto-design` の手順9 F5 など）。選んだ結果は `.claude/rules/dev-practices.md`「まとめて合意を取ってよい」の合意として扱える |

選択肢を聞く手段の境目: 項目が3つ以下で、画像を見なくても選べるなら、返答の中で選択肢の UI（AskUserQuestion）で聞く（`CLAUDE.md` 出力テンプレの1）。項目が4つ以上か、画像・事例・触る物を見て選ぶなら判断盤を出す

## 出し方を決める

rdd の事実ブロック「運用環境」の **判断盤の出し方**（`/setup` が聞いて書く）を見る。どの rdd を読むかは `/setup` の「どの rdd を読み書きするか」に従う（ai-template 自身では `meta/rdd.ai-template.md`）。

| 答え | レポート | 判断盤 |
|---|---|---|
| Artifact が使える | 保存したファイルを Artifact で公開する（既定は非公開。共有するかは人間が決める） | 同じく Artifact で見せる。選んだ結果は「コピー」ボタンで人間が会話に貼る |
| Artifact が使えない | 保存したファイルをローカルで開く（macOS なら `open <パス>`）。パスを返答に書く | 同じくローカルで開く。選んだ結果をコピーして会話に貼ってもらう |

記録が無ければ `/setup` の手順3と同じく聞く（推測で決めない）。

## 保存先

| リポジトリ | 置き場 |
|---|---|
| 通常のプロジェクト | `doc/generated/reports/YYYY-MM-DD-スラッグ.html` |
| ai-template 自身 | `meta/reports/YYYY-MM-DD-スラッグ.html` |

- 公開する前に、必ずこの置き場に保存する（公開するのはこのファイル）
- **判断盤は、呼ぶ側のスキルが置き場を決めていればそちらが正**（例: `design-language-options` の判断盤は設定集の中）。決めていなければ上の置き場に保存する。どちらの置き場でも、レポート一覧には載せる（人間の決定）
- **同じテーマの続きは、新しいファイルを作らず同じファイルを更新して URL を保つ**

## レポートの書き方

- 日本語で書く。構成の目安: 結論のリード文 → 構成図 → 作業フロー図 → 結果一覧表 → 補足
- 図は Mermaid（フローチャート、シーケンス図など）を基本にし、`<pre class="mermaid">` に書く
  - **Artifact は Mermaid を自分で描くので、ライブラリを読み込まない**（Artifact の決まりに「読み込まない」と明記されている）
  - **ローカルで開いたときだけ** mermaid.js を読み込む（人間の決定）。版は固定する（固定した版の値は下のコードの `@` のあと。上げるときは npm で版とライセンスを確かめてから、このスキルの値を書き換える）:
    ```html
    <script type="module">
      // ローカル（file:）で開いたときだけ読み込む。Artifact は自分で描くので読み込まない
      if (location.protocol === 'file:') {
        const { default: mermaid } = await import('https://cdn.jsdelivr.net/npm/mermaid@12.1.0/dist/mermaid.esm.min.mjs');
        mermaid.initialize({ startOnLoad: false });
        await mermaid.run({ querySelector: '.mermaid' });
      }
    </script>
    ```
  - ローカルで開くときはネットにつながっている必要がある。CDN のスクリプトには改ざん検知（SRI）を付けていない（mermaid は読み込んだあとに追加のファイルを取りに行くので、入口だけに付けても全体は守れない。版の固定で受け入れる）
- 人間が図をドラッグして手で編集したいときは draw.io MCP（`mcp__drawio__*`）を使う。レポートに埋め込むなら Mermaid、対話的に編集するなら draw.io

## 判断盤の作り方

- **1項目 = 1つの問い**。項目ごとに次を並べる:
  - 何を決めるか（人間が知らない語は先に説明する）
  - 選択肢と、それぞれを選ぶと何が起きるか
  - 決めないと何が止まるか
  - 推しと根拠（SSOT のパス。無ければ「根拠なし・推測」）
  - 画面や事例を見て選ぶものは、画像・スクリーンショット・起動方法を添える
- 「その他（自由記入）」の欄を必ず置く
- **選んだ結果をまとめてコピーするボタン**を置く。コピーされる文は、項目の ID・選んだ選択肢・自由記入をそのまま並べた形にし、会話に貼れば合意として読める形にする
- 選んだ状態はブラウザの中だけに置く（保存が要るものは会話に貼ってもらう）
- 第三者の画像（事例）を埋め込まない。相対パスで参照し、共有する版には引用元のリンクだけを載せる（`design-language-options` の「成果物の置き場」）。相対パスの画像は Artifact では表示されないので、画像を見て選ぶ判断盤はローカルで開いて見てもらう（Artifact の版には引用元のリンクを並べる）

## レポート一覧（レポートインデックス）を更新する

1. 保存先と同じディレクトリの `index.html`（レポート一覧）に、日付・タイトル・1〜2行の要約・公開先の URL・保存パスの行を**新しいものが上**になるよう足し、**一覧を同じ URL で再公開する**（手順2）
2. 一覧の公開先の URL は、`index.html` 冒頭の HTML コメント `<!-- artifact-url: ... -->` に記録してある。別のセッションから更新するときは、この URL を Artifact ツールの `url` パラメータに渡して**同じ URL を保つ**
3. `index.html` が無ければ、初回として新しく作り、公開したあとに URL をコメントで記録する
4. 一覧を更新したら、返答の最後の行を `レポート一覧: <一覧の URL>` にする（`CLAUDE.md` の出力テンプレ。フッターのリンクバッジがこの形式を拾う）
5. Artifact が使えない環境では、一覧もローカルのファイルとして更新し、返答の最後の行は `レポート一覧: <一覧のパス>` にする

## やってはいけない

- 保存せずに公開する（次のセッションから辿れなくなる）
- 同じテーマの続きで新しい URL を作る
- 判断盤で、選ばれた結果を AI が推測で補う（選ばれていない項目は「決めていない」として扱う）
- 判断盤の結果を、合意の範囲を超えて書き込む（選ばれた項目だけを書く）
