# /setup — 前提・引き継ぎ・環境・今日のゴール

セッションは必ずここから始める（`/clear` → `/setup`）。4段を順に進め、各段は短く済ませる。

## 入力: $ARGUMENTS（任意）
- 今日やりたいことの概要（例: `PRレビュー対応 #123`）。あれば手順4のゴールの候補にする

## どの rdd を読み書きするか

| リポジトリ | 読み書きする rdd |
|---|---|
| 通常のプロジェクト | `doc/input/rdd.md` |
| **ai-template 自身**（`meta/rdd.ai-template.md` があるリポジトリ） | **`meta/rdd.ai-template.md`**。`doc/input/rdd.md` は配布用の空の雛形なので、読まない・書かない |

## 1. 前提を読む

rdd の先頭の「AI用：事実ブロック」を読み、技術スタックと制約に合うスキルを選ぶ。未記入の項目は推測で埋めない（必要になった時点で短問で聞く）。

## 2. 引き継ぎを読む

存在するものだけ読む（無ければ飛ばす）。

| 読むもの | 何が分かるか |
|---|---|
| `.claude/session-context.md` | 前回 `/session-end` が残した再開用の要約 |
| `history/journal.md` の最新の日付エントリ | 前回やったこと・翌日への引き継ぎ |
| `history/loop-state.md` | 止まっている自律ループ。`in_progress`（中断）と `blocked_by_*`（人間の判断待ち）を拾う（種類は `auto-loop-core`）。止まったのが `auto-design`（`auto-build` から呼ばれたときも含む）なら、値のファイル（`doc/input/design/*.json`）の `meta.provisional` と `undecided` も一覧にして見せる（仮の値が確定の顔で残っているため） |
| タスクボード（rdd の「運用環境」に書いてあるもの） | いまやっていること・次にやること |

止まっている自律ループや判断待ちがあれば、今日のゴールの候補として最初に示す。

## 3. 環境を確かめる

rdd の「運用環境」に**記録が無い項目だけ**聞く（記録があれば聞かない。節そのものが無ければ足す）。選択肢があるものは選択肢の UI（AskUserQuestion。無い環境では番号つきの質問）で聞く。答えは「運用環境」に書く。`doc/input/` や `meta/` への書き込みなので、書く文面を見せて合意を取る（`.claude/rules/dev-practices.md`「一時と確定を分ける」）。

| 項目 | 聞くこと | 既定 |
|---|---|---|
| タスクボード | GitHub Projects / Orca / Linear / 使わない | **置かない**（未設定なら必ず聞く） |
| デザインツール | Figma MCP が使えるか（Claude Code なら `claude mcp list` で確かめてから聞く） | — |
| 参考事例 | Mobbin MCP が使えるか。使えなければ Design Inspiration 系のサイトから集める | — |
| 判断盤の出し方 | Artifact が使えるか。使えなければローカルの HTML を開き、判断をコピーして貼る形にする | — |
| Web の公開範囲（Web のときだけ） | 検索に出すか／AI の学習に使わせるか／AI の検索・回答に出すか／出さないページ。**4つを別々に聞く**（各社で学習用と検索用のボットが分かれている）。答えは `web-discoverability` が robots.txt・noindex の設定に使う | —（決めていない。Web のときは必ず聞く） |

- **できないことは、ここでまとめて聞いて代わりの経路を決める**（作業の途中で詰まらないように）
- Figma MCP が未登録・未起動なら、`/design-ssot` の事前チェック手順に従う

## 4. 今日のゴールを決めて GO をもらう

```markdown
## 今日のゴール
- ゴール: {1文で、完了した状態を書く}
- 完了条件: {具体的に2〜3個。「〜する」ではなく「〜が終わっている」}
- 今日やらないこと: {あれば}
- 区切り（コミットする点）: {1〜3個}
```

- **この計画で進めてよいかを確認し、GO をもらってから着手する**
- 1セッション1〜2タスクを目安にする。大きければ分けて、今日の分だけをゴールにする
- スコープと優先度は人間が決める。AI は候補を出すだけ（`.claude/rules/dev-practices.md`）
- 計画に時間をかけすぎない

## 関連

- `/session-end` — 区切り・終了時に進捗と再開用の要約を残す（次の `/setup` がそれを読む）
- `auto-loop-core` — 自律ループの状態の種類と再開の仕方
