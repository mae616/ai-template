# [テンプレート保守] 投函箱の構築（このPC用）

`/template-feedback` の**前段**。取り込む前に、このマシンの投函箱を作る。

## なぜPCごとに構築するのか

投函箱の中身（受け取った送り状）は**各PCローカル**で、Git 追跡外にしている。
受け取った送り状には出典マシンの**絶対パス**が載るため、OSS配布物・公開リポジトリに混ぜられないからだ。

代償として、clone 直後の投函箱は `README.md` だけになる。
このコマンドで、そのマシンの実際のディレクトリ配置から投函箱を組み直す。

## 実行条件

- カレントが ai-template リポジトリであること

## 手順

### 1. 走査ルートの確定
- デフォルトは sibling: `ls ../*/doc/output/to-template.md`
- **sibling の外にプロジェクトがあるPCもある**。心当たりを人間に確認し、指定があれば走査対象に加える
- ai-template 自身の `doc/output/to-template.md`（配布用の空雛形）は対象外

### 2. 未取込項目の抽出
- 各送り状から状態が `未取込` の項目を拾う（空雛形・記入例コメントは除く）
- 未取込が0件のプロジェクトは投函箱を作らない（空ファイルを増やさない）

### 3. 投函箱への materialize
- `doc/input/from-projects/<プロジェクト名>.md` が
  - **無ければ**: 雛形を作り、`出典リポジトリ` に**このPCで解決した絶対パス**を埋める
  - **あれば**: 上書きせず、正本にあって投函箱に無い項目だけを追記候補として提示する
- `解決済みファイル`（直した実物のパス）は**送り状本文からは自動で分からない**。空欄で置き、人間に確認して埋める。ここが投函箱の主価値なので、空のまま放置しない

### 4. 確認
- 作成/更新したファイルと、各項目の未取込件数を一覧で示す
- そのまま `/template-feedback` に進むか人間に確認する

## 投函箱ファイルの形

冒頭にメタ情報、以降は項目ごとに **種別 / 反映先候補 / 出典リポジトリ / 解決済みファイル / 状態**。
詳細は `doc/input/from-projects/README.md` を参照する。

## 落とし穴

- **正本を書き換えない**: プロジェクト側の `doc/output/to-template.md` はこのコマンドでは触らない（状態を倒すのは `/template-feedback` の役目）
- **絶対パスを相対に直さない**: ローカル専用ファイルなので絶対パスで良い。取り込み時に実物を読めることが優先
- **取込済の項目まで materialize しない**: 二重取り込みの元になる
