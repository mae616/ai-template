# from-projects — 各プロジェクトからの送り状インボックス

各プロジェクトで得た「汎用化できる学び」の**投函箱**。
`/template-feedback` で取り込む前の、未処理の受け皿として使う。

## なぜここに置くか

送り状の正本は各プロジェクトの `doc/output/to-template.md` にある。
`/template-feedback` は sibling を走査するので、仕組みとしてはそれで拾える。

ただし実運用では**取りこぼす**。理由は2つ。

1. ai-template を開いたとき、**他リポジトリの中身は目に入らない**。存在を思い出せない
2. プロジェクト側リポジトリを push しないと、他の環境から参照できない

そこで、学びを得た時点で**ここにも写しを置く**。
ai-template を開けば未処理の学びが目に入る状態にする。

## 競合しない理由

このフォルダは**投函箱であって、テンプレート本体ではない**。

- `.claude/skills/`・`.claude/rules/`・`CLAUDE.md` は**触らない**
- **1プロジェクト＝1ファイル**（`<プロジェクト名>.md`）。共有ファイルを複数プロジェクトが書かない

判断の集約は従来どおり `/template-feedback` の側で直列に行う。
「プロジェクトはテンプレート本体を編集しない」という競合回避モデルは維持される。

## ファイルの書き方

ファイル名は `<プロジェクト名>.md`。各項目に次を書く。

| 欄 | 内容 |
|---|---|
| 種別 | 新規skill / 既存skill追記 / rules追記 / CLAUDE.md補強 / 新規の仕組み |
| 汎用化した形 | プロジェクト固有の文脈を外した記述 |
| 反映先候補 | `.claude/rules/xxx.md` 等（あくまで候補） |
| **出典リポジトリ** | **ローカルの絶対パス**。取り込み時に実物を読めるようにする |
| **解決済みファイル** | **直した実物のパス**。テンプレートに写す元になる |
| 状態 | 未取込 / 取込済（YYYY-MM-DD / 短縮hash） |

「解決済みファイル」を書くのが要点。
取り込み時に**動いている実物を読んでから**テンプレートに写せる。
送り状の記述だけを頼りに書き直すと、検証済みの内容が劣化する。

## このフォルダの中身はGit追跡外（各PCローカル）

`README.md`（このファイル）だけを追跡し、**受け取った送り状の実体は追跡しない**。

受け取った送り状には出典マシンの**絶対パス**が載る。それが価値の源（取り込み時に実物を読める）だが、
ai-template は OSS として公開・配布されるため、公開物・配布物に個人のパスを混ぜられない。
`.gitignore` と `scripts/apply_template.sh` の両方で除外している（公開と配布は別経路なので両方いる）。

代償として、**新しいマシンで clone すると投函箱は空**になる。
そのPC用に組み直すコマンドが `/template-inbox`。sibling を走査し、未取込の学びを写しとして materialize する。

## 取り込み後

`/template-feedback` の台帳更新で、**このファイルと、プロジェクト側の正本の両方**の
状態を `取込済` に倒す。片方だけだと次回に二重取り込みされる。
