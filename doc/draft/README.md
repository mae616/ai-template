# doc/draft/ — 発酵中のドキュメント（未合意）

> **ここは「まだ合意されていないもの」の置き場**。`doc/input/` とは扱いが違う。

## input と draft の違い

| | `doc/input/` | `doc/draft/`（ここ） |
|---|---|---|
| 状態 | **合意済み** | **未合意** |
| AIの扱い | **前提として扱う**（守るべき制約） | **参考にする**（決定事項として扱わない） |
| 中身 | 要件（rdd.md）・アーキテクチャ | プロトの学び・設定集・検討中の案 |
| 誰が書くか | 人間の合意を経て書き込む | 作業の過程で自由に貯める |
| 消えてよいか | だめ（SSOT） | よい（発酵の途中経過） |

## なぜ分けるか

プロトタイプが完走したことと、その中身が要件になることは**別の話**。
両者を同じ場所に置くと、作業の過程で生まれた判断が、合意を経ないまま
「決まっていること」として次のセッションに引き継がれる。

> 実測: プロト工程で `rdd.md` に追加された設計判断を全ログで逆引きしたところ、
> 追跡できた6件すべてがAI初出だった（`meta/adr-lite.md` ADR-026 / 2026-08-27 のレポート）。

置き場所を分けることで、**AIが「これは前提か、参考か」をパスで判断できる**ようにする。

## 昇格の手続き

`draft/` の中身を `input/` へ上げるには、**人間の合意が要る**。

```
draft/ に貯める  →  昇格候補として提示  →  人間が決める  →  input/ へ書く
                    （AIは候補を出すだけ）    （ここが関所）
```

- AIは昇格候補を**提示するだけ**。上げるかどうかは判断しない
- 上げるときは、**input/ に書き込む文面そのもの**を見せて合意を取る
- 迷ったら `draft/` に留める（`judgment-harness` の「メモとSSOTを分ける」）

## 置くもの（例）

```
doc/draft/
├── design/setting-book/   … プロト連作の設定集（proto-loop）
└── （検討中の案・調査メモ・未確定の仕様）
```
